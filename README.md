# نظام المخازن — نسخة الإنتاج (Supabase)

هذه نسخة كاملة من النظام تعمل بقاعدة بيانات حقيقية على Supabase، بدون أي اعتماد على منصة Claude.
نفس الشاشات والمزايا بالضبط (المخازن، الأصناف، الأوردرات، المصانع، المستخدمين)، لكن البيانات الآن محفوظة في قاعدة بياناتك الخاصة مع نسخ احتياطي تلقائي وتسجيل دخول حقيقي.

---

## الخطوة 1: إنشاء مشروع Supabase

1. روح على [supabase.com](https://supabase.com) واعمل حساب مجاني (بجيميل).
2. دوس **New Project**، اختار اسم ومنطقة قريبة، وحط باسورد لقاعدة البيانات (احفظه في مكان آمن).
3. استنى دقيقة لحد ما المشروع يخلص إنشاء.

## الخطوة 2: تشغيل ملف قاعدة البيانات

1. من القائمة الجانبية اليسرى: **SQL Editor** → **New query**.
2. افتح ملف `supabase/schema.sql` من هذا المجلد، انسخ محتواه كامل، والصقه في المحرر.
3. دوس **Run**. هيتنشئ كل الجداول والصلاحيات دفعة واحدة.

## الخطوة 3: تعطيل تأكيد الإيميل (مهم جدًا)

المستخدمين في النظام مالهمش إيميلات حقيقية (بيسجلوا بالاسم بس)، فلازم تقفل خاصية تأكيد الإيميل:

1. من القائمة الجانبية: **Authentication** → **Providers** → **Email**.
2. دوّر على **Confirm email** وقفّله (Disable).
3. احفظ.

## الخطوة 4: هات مفاتيح المشروع

1. **Project Settings** (الترس ⚙️) → **API**.
2. هتلاقي **Project URL** و **anon public key** — انسخهم.
3. في مجلد المشروع، انسخ ملف `.env.example` وسمّيه `.env`، وحط فيه القيمتين:
   ```
   VITE_SUPABASE_URL=https://xxxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJ...
   ```

## الخطوة 5: نشر الـ Edge Functions (لإدارة المستخدمين)

عشان الأدمن يقدر يضيف/يحذف مستخدمين من غير ما يخرج من حسابه هو، النظام محتاج دالتين صغيرتين شغالة على سيرفر Supabase.

1. ثبّت أداة Supabase CLI (خطوة مرة واحدة):
   ```
   npm install -g supabase
   ```
2. سجّل دخول واربط المشروع:
   ```
   supabase login
   supabase link --project-ref your-project-ref
   ```
   (`your-project-ref` تلاقيه في رابط مشروعك على Supabase، أو في Project Settings)
3. انشر الدالتين:
   ```
   supabase functions deploy create-user
   supabase functions deploy delete-user
   ```

هما بيستخدموا مفتاح "service role" تلقائيًا من نفس مشروعك، مش محتاج تحط حاجة يدوي.

## الخطوة 6: تجربة النظام محليًا (اختياري)

```
npm install
npm run dev
```

هيفتح على `localhost` وتقدر تجرب إنشاء حساب الأدمن الأول والتأكد إن كل حاجة شغالة قبل النشر.

## الخطوة 7: النشر على الإنترنت (Vercel)

1. ارفع المجلد على GitHub (repo جديد).
2. اعمل حساب على [vercel.com](https://vercel.com) بحساب GitHub.
3. **Add New Project** → اختار الـ repo → **Import**.
4. **مهم**: قبل الضغط على Deploy، افتح **Environment Variables** وضيف:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
   (نفس القيم اللي في ملف `.env` بتاعك)
5. دوس **Deploy**. بعد دقيقة هتاخد رابط ثابت شغال للجميع.

## ملاحظات مهمة

- **الرقم السري بقى لازم يكون 6 أرقام على الأقل** (بدل 4) لأن Supabase Auth بيشترط كده كحد أدنى للباسورد.
- **أول حساب بيتسجل** (المسؤول الأول) بيسجل نفسه مباشرة. أي حساب بعد كده (سواء أدمن أو موظف مخزن) لازم يتضاف من شاشة "المستخدمين" داخل النظام (زرار "إضافة مستخدم") — مش من شاشة تسجيل الدخول.
- **الأمان**: أي مستخدم مسجّل دخول (أدمن أو موظف) عنده صلاحية قراءة وكتابة على الأصناف والحركات والأوردرات من ناحية قاعدة البيانات مباشرة؛ التفرقة بين الصلاحيات متحكم فيها من الواجهة حاليًا. مناسب لفريق صغير موثوق فيه. تفاصيل أكتر في تعليقات ملف `supabase/schema.sql`.
- سجل الحركات (`transactions`) بيجيب آخر 500 حركة بس في كل تحميل، عشان الأداء. لو حبيت أرشفة أو تصدير كامل لاحقًا نقدر نضيفها.
